## 一、总体评价（面试官视角）

**亮点（讲项目时主动说的）：**

1. **组件拆分彻底**：PlayerController 已瘦身为纯编排器（输入/移动/血量/战斗/特效全部下放组件），符合单一职责，消除 God Class。
2. **HFSM 三层并行设计真实落地**：BASE 常驻 + ACTIVE 并行 + ABNORMAL 独占，`MUTEX/ALLOW` 并存策略、跨层切换返回值约定（`string` / `{layer,name}`）都是完整的调度语义，不是玩具。
3. **热更链路完整**：C# Bridge（`PlayerLuaBridge`）→ Lua 状态机 → 状态文件，新增状态纯 Lua 侧完成；`LuaVerifyMenu` 提供了编辑器验证工具。
4. **性能意识到位**：`OverlapCircleNonAlloc` 复用 buffer、对象池软上限、`WaitForSecondsRealtime` 规避 HitStop 死锁、`static readonly WaitForSeconds` 避免协程分配。
5. **事件解耦**：UI/血量/死亡通过 EventCenter 通信，无直接类引用。

**薄弱点（面试官会追问的，必须准备好话术）：**

| # | 薄弱点 | 状态 |
|---|--------|------|
| 1 | PlayerController 直接暴露给 Lua（无 Facade） | P1 规划中，已有应答话术 |
| 2 | 跨语言调用每帧装箱/GC | P2 优化项，需能说清方案 |
| 3 | xLua 反射回退（未生成代码）只在编辑器可用，出包前必须跑 CodeGen | **本次已加 `[LuaCallCSharp]`** |
| 4 | 旧 Input Manager（`Input.GetAxisRaw`），未用新 Input System | 说明是 URP 2D 模板默认，面试可讲迁移方案 |
| 5 | Addressables 包未安装，`AddressablesLoader` 走 `#else` 分支 | **简历表述必须同步**（见简历部分） |

## 二、已修复问题（本次评审 + P0 路线图合并完成）

### 🔴 P0-1【崩溃】HFSM 跨层切换 `{}` 崩溃
- **位置**：`Lua/Framework/Fsm/HFSM.lua` `ResolveNext`
- **问题**：`hurt.lua` 受击结束（贴地）返回 `{ }`，`ResolveNext` 对 table 执行 `ChangeState(next.layer=nil, ...)` → `layers[nil]` 索引崩溃。
- **修复**：`{ }` 语义定义为「仅清空本层，回 BASE 当前状态，不额外切换」；`next.layer` 存在才执行跨层 ChangeState。

### 🔴 P0-2【功能缺失】MUTEX 输出锁从未真正生效
- **位置**：`HFSM.lua` + `ground.lua` / `air.lua`
- **问题**：dash 期间 BASE 层（ground/air）每帧无条件写 `SetVelocityX`，把冲刺速度瞬间覆盖，冲刺实际失效；MUTEX 锁只包住了 `active.LogicUpdate` 一瞬，无实际作用。
- **修复**：HFSM 帧首计算 `mutexActive` 并调用 `base.current.SetOutputLocked(core, mutexActive)`；ground/air 实现 `outputLocked` 门控——锁定期间抑制位移/跳跃/攻击输出，**落地/贴墙检测照常运行**（物理事实不被锁），完全对应面试文档 Q2 的应答设计。

### 🔴 P0-3【功能缺失】冲刺冷却从未计时
- **位置**：`dash.lua` / `ground.lua` / `air.lua`
- **问题**：`DashCooldownTimer` 无任何地方设置/递减，冲刺无冷却（无限连冲）。
- **修复**：`dash.Enter` 设置 `DashCooldownTimer = dashCooldown`；ground/air 每帧递减（锁定期间也递减）。

### 🔴 P0-4【功能缺失】跳跃预输入（Jump Buffer）从未被消费
- **位置**：`ground.lua`
- **问题**：C# 侧 `PlayerInput` 维护了 `JumpBufferTimer`，但所有状态只查 `JumpDown`（单帧），缓冲功能是死代码。
- **修复**：`ground.lua` 跳跃条件改为 `JumpBufferTimer > 0`（落地前 0.2s 内按跳 → 落地自动起跳），与简历中「跳跃预输入」claim 对齐。

### 🔴 P0-5【功能缺失】受击未接入 HFSM ABNORMAL 层
- **位置**：`PlayerHealth.cs` / `PlayerLuaBridge.cs` / `EventCenter.cs` / `hurt.lua`
- **问题**：`hurt.lua` 存在但从未被激活（`luaChangeState` 在 Bridge 里从未被调用）；受击只靠 `PlayerController.Update` 的 `IsHurting` 短路，ABNORMAL 层是空转。
- **修复**：EventCenter 新增 `PlayerHurt` 事件 → `PlayerHealth.TakeDamage` 广播 → `PlayerLuaBridge` 订阅并 `ChangeState(3, "hurt")` → HFSM ABNORMAL 独占冻结 BASE/ACTIVE → `hurt.lua` 检测 `IsHurting` 结束后 `{ }` 恢复。同时修正 `PlayerController.Update`：**输入先 Tick 再短路**，受击期间输入状态不再冻结（修复受击结束残留 JumpDown 的隐式 bug）。

### 🟠 P0-6【多实例 bug】敌人 Lua 状态共享模块级变量
- **位置**：`patrol/chase/attack/telegraph/hurt_state.lua` + `enemy_fsm.lua`
- **问题**：状态表是 require 缓存的单例，`local timer`（attack/telegraph/hurt）被**所有敌人共享**——两只敌人同时攻击时计时器互相覆盖。
- **修复**：5 个状态模块改为导出**工厂函数**，`enemy_fsm.Init` 为每只敌人调用 `factory()` 产出独立状态实例（闭包持有各自 timer）。这也是面试加分点：「状态实例化 vs 单例」的取舍。

### 🟠 P0-7【不一致】Lua 接管时敌人受击仍走 C# 状态机
- **位置**：`Enemy.cs` `TakeDamage` / `EnemyLuaBridge.cs`
- **问题**：`useLuaFSM=true` 时 C# `StateMachine.ChangeState(hurtState)` 仍被执行，但 C# 状态机已不被 Update 驱动 → 受击硬直无效。
- **修复**：`useLuaFSM` 时改调 `EnemyLuaBridge.ChangeState("hurt")`；Bridge 新增公开方法。

### 🟠 P0-8【出包隐患】xLua 反射回退仅编辑器可用
- **位置**：全部被 Lua 调用的 C# 类型
- **问题**：只有两个 Bridge 有 `[LuaCallCSharp]`；`PlayerController` 等全靠 xLua 编辑器的反射回退（`ObjectTranslator` 日志会打印 "not gen, using reflection instead"）。**打包 IL2CPP/无 `UNITY_EDITOR` 时反射回退被裁剪，Lua 调 C# 直接失败。**
- **修复**：给 `PlayerController / PlayerMovement / PlayerInput / PlayerCombat / PlayerHealth / PlayerEffect / Enemy` 补 `[LuaCallCSharp]`。后续在 Unity 里执行 `XLua/Generate Code` 生成代码即可出包。

### 🟠 P0-9【存档 bug】武器读取失败清空武器栏
- **位置**：`PlayerCombat.cs` `OnLoad`
- **问题**：武器资源在 `Assets/Data/Weapons`（非 Resources），`Resources.Load("Weapons/...")` 必然失败；原逻辑先 `Clear()` 再加载 → 读档后空手。
- **修复**：先完整加载到临时列表，成功才整体替换；失败仅告警不破坏现状。**另建议：要么把武器资产移入 `Resources/Weapons/`，要么后续换 Addressables 加载**（二选一，与 P2-5 联动）。

### 🟡 P1-10【规范】UI 引用手动拖拽 + 按钮 Inspector 绑定（违反项目 CLAUDE.md 规范）
- **位置**：`UIManager.cs` + `SampleScene.unity`
- **修复**：UIManager 改为 `Awake` 中 `transform.Find("Canvas/HealthBar_BG/HealthBar_Fill")` / `Find("Canvas/Panel")` 自动获取；重启按钮改为 `onClick.AddListener(RestartGame)`，并已从场景 YAML 移除 Inspector 的 `m_OnClick` 绑定（避免双重触发）。

### 🟡 P1-11【规范】类名笔误 `PLayerEffect`（文件已叫 PlayerEffect.cs）
- **修复**：类名改 `PlayerEffect`，与文件名一致（MonoBehaviour 类名必须匹配文件名，否则 Inspector 无法添加）。场景引用按 GUID 解析不受影响。

### 🟡 P1-12【健壮性】`PlayerCombat.OnLoad` 防御
- 见 P0-9，合并完成。

## 三、未修复问题（建议 + 面试话术）

### P2 级（当前不修，但要知道怎么说）

| # | 问题 | 说明 / 面试话术 |
|---|------|----------------|
| P2-1 | `EventCenter` 字符串事件名 | 运行时拼写错误无编译期检查；可演进为 `static class GameEvents` 常量或类型安全的事件表。面试主动说「知道 trade-off，demo 规模字符串更灵活」。 |
| P2-2 | Lua→C# 每帧 `Call(player)` 装箱 | `LuaFunction.Call` 返回 `object[]`；P2 方案：缓存强类型 delegate（`LuaFunction.GetAction<PlayerController>` 或 `LuaEnv` 的 `LuaFunction<Action>` 泛型）、移动参数打包结构体一次传入。 |
| P2-3 | 状态对象为模块级单例（玩家侧） | 单玩家下安全；若做双人/镜像会互相污染。设计上「单例状态 + core 参数」是常见折中，面试可讲。 |
| P2-4 | 旧 Input Manager | 兼容模板默认；迁移新 Input System 的话 InputAction 资产 + `PlayerInput.Tick` 接口不变。 |
| P2-5 | Addressables 未安装 | `HAS_ADDRESSABLES` 未定义，`AddressablesLoader` 实际未启用。**要么装包跑通，要么简历删掉「掌握 Addressables」**（否则一问就露）。 |
| P2-6 | `Projectile.DestroyProjectile` 命中特效 `Instantiate` 未走池 | 低频对象，可接受；说「高频才需要池」即可。 |
| P2-7 | 敌人 `CanSeePlayer` 无视线遮挡检测 | 只说距离+高度；可加 `Physics2D.Raycast` 遮挡判定（好讲）。 |
| P2-8 | `BTConfig` 无环检测 | 编辑器里拖出环会栈溢出；可加编译期 DFS 环检测（面试加分小功能）。 |
| P2-9 | `SaveManager` 全场景 `FindObjectsByType` 扫存档 | 规模小可接受；说「按接口收集 ISaveable 是解耦设计」。 |
| P2-10 | `HFSM.ChangeState` 同帧多次切换不合并 | 面试文档 Q3 已有应答（延迟切换+帧末合并是 V2 方向）。 |
| P2-11 | `PlayerHealth` 受击无敌帧仅 0.2s 硬直 | 受击状态本身就是无敌帧；若要更细可加 `invincibleDuration` 配置。 |
| P2-12 | `wall_slide` 无输出锁实现 | 冲刺撞墙会进墙滑并打断冲刺（其实手感可接受）；如要严格互斥，给 wall_slide 也实现 `SetOutputLocked`。 |
