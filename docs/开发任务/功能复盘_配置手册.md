# 功能复盘（二）：配置手册 —— 每个系统由什么组成、要配哪些字段

> 最后更新：2026-09-10

> 配套阅读：`功能复盘_设计取舍.md`（为什么这么拆）
>
> 阅读方式建议：**一次只看一个系统**。每个系统都给四块：
> ① 组成（谁是谁）② 数据流（从触发到结果）③ 配置清单（字段/值/作用）④ 扩展点（要加东西改哪里）

## 0. 先记住这张"骨架图"

所有系统都长在同一个骨架上。**看懂这张图，后面每个系统都只是往里填东西。**

```
玩家身上的组件                        事件总线                    表现层
─────────────────                  ─────────────              ─────────────
PlayerController                                                UIManager
 ├ PlayerInput      ──输入                                    ├ 血条
 ├ PlayerMovement                                                ├ 金币文字
 ├ PlayerCombat     ──武器/攻击 ──→ WeaponChange ──────────────→ 背包高亮
 ├ PlayerHealth     ──血量/受击 ──→ PlayerHealthChange/PlayerHurt
 │                                  PlayerDead/PlayerDie
 ├ PlayerInventory  ──道具    ──→ InventoryChange ─────────────→ 背包列表
 ├ PlayerWallet     ──金币    ──→ CoinChange ──────────────────→ 金币文字
 └ PlayerClimb      ──爬梯

世界物体
 TreasureChest / SignPost / ShopNPC / Door
   └ 靠 Trigger 检测玩家靠近 → 头顶提示 → 按 E → 调对应的面板

面板（UI）
 ShopPanel / InventoryPanel / SignPanel / UIManager
   └ 全部只"读数据 + 显示"，不直接改游戏逻辑
```

**一条铁律**：箭头方向**只能往下走**（逻辑 → 事件 → 表现）。如果表现层反过来改逻辑，就会绕成环。

## 1. 事件中心（EventCenter）—— 一切的粘合剂

### 组成

| 东西 | 说明 |
|---|---|
| `EventCenter.Instance` | 全局单例，挂在 GameManager 上（DontDestroyOnLoad） |
| `EventCenter.EventType` | 枚举，**所有事件名的唯一定义处** |
| `AddListener<T>(name, action)` | 订阅（泛型版用于带参数的事件） |
| `Broadcast(name, args...)` | 广播 |

**现有事件（10 个）**：

| 事件 | 参数 | 谁发 | 谁听 |
|---|---|---|---|
| `PlayerHealthChange` | `int current, int max` | `PlayerHealth` | `UIManager`（血条） |
| `PlayerHurt` | 无 | `PlayerHealth` | `PlayerLuaBridge`（进受击状态） |
| `PlayerDead` | 无 | `PlayerHealth`（演出结束） | `UIManager`（弹结算） |
| `PlayerDie` | 无 | `PlayerHealth`（死亡瞬间） | `PlayerLuaBridge`（清状态层） |
| `CoinChange` | `int coins` | `PlayerWallet` | `UIManager`（金币文字） |
| `WeaponChange` | `int index` | `PlayerCombat` | `InventoryPanel`（高亮） |
| `InventoryChange` | 无 | `PlayerInventory` | `InventoryPanel` |
| `DoorOpened` | 无 | `Door` | 目前没人听（留给音效/成就） |
| `BossDefeated` | 无 | `Enemy.FinishDeath()` | `UIManager`（胜利面板） |
| `PlayerStateChange` | — | 预留 | — |

### 配置：**没有字段要配**，但要遵守两条规则

1. **事件名一律从枚举取**：`EventCenter.EventType.CoinChange.ToString()`，**绝对不要手写 `"CoinChange"` 字符串** —— 拼错了编译器不管，运行时静默不触发。
2. **`AddListener` 和 `RemoveListener` 必须成对**，而且放在 `OnEnable`/`OnDisable`（不是 `Awake`/`OnDestroy`），这样物体禁用时会自动退订。

### 排错口诀

> **"事件发了但没反应" = 90% 是没人订阅，或者订阅方在 Awake 里订阅（EventCenter 还没就绪）。**
>
> 你踩过这个：`BossDefeated` 广播了，但 `UIManager.ShowVictoryPanel` 第一行是 `if (victoryPanel == null) return;` —— 静默返回。**修法是让它响亮地失败**（`Debug.LogError`）。

### 扩展点

加事件 = 在 `EventType` 枚举尾部**追加**一项（不要插在中间，会让已序列化的值错位）。

## 2. 经济链：掉落 → 钱包 → UI

### 数据流

```
敌人死亡 / 宝箱打开
   └ LootTable.Roll()  →  随机一条掉落项
        └ 按 minAmount~maxAmount 生成 N 个金币预制体（走对象池）
             └ CoinPickup.OnTriggerEnter2D(玩家)
                  └ PlayerWallet.AddCoins(value)
                       └ 广播 CoinChange
                            └ UIManager.UpdateCoinText(coins)
```

### 组成

| 类 | 职责 |
|---|---|
| `LootTable`（SO） | 掉落表：一条条 `entry`（预制体 + 权重 + 数量范围） |
| `CoinPickup` | 挂在金币预制体上：磁吸 + 拾取 |
| `PlayerWallet` | 只管一个数字 `Coins` + `AddCoins` / `TrySpend` |

### 配置清单

**`LootTable` 资产**（例：`Assets/Prefabs/ChestLoot.asset`、`SlimeLoot.asset`）

| 字段 | 说明 |
|---|---|
| `entries[].itemPrefab` | 掉什么预制体（金币预制体） |
| `entries[].weight` | 权重（多条时按权重随机） |
| `entries[].minAmount` / `maxAmount` | 数量范围 |

**`CoinPickup`（在金币预制体上）**

| 字段 | 建议 | 作用 |
|---|---|---|
| `value` | 1 | 这一枚值多少金币 |
| `magnetRadius` | 2 | 玩家进入这个距离开始被吸 |
| `magnetSpeed` | 8 | 吸附速度 |

**挂载点**：`Enemy.lootTable`（敌人掉落）、`TreasureChest.lootTable`（宝箱掉落）—— 两者用**同一套** `LootTable`。

### 设计要点

- **`PlayerWallet` 不关心金币从哪来** —— 敌人掉的、宝箱开的、以后任务奖励的，都只调 `AddCoins`。这就是"职责单一"的实际好处。
- **`TrySpend` 返回 bool** —— 商店买不起时靠它判断，而不是先查 `Coins` 再扣（那样两次操作之间可能状态变了）。

### 扩展点

| 想加什么 | 改哪里 |
|---|---|
| 新的掉落物 | 新建一个预制体（带 `CoinPickup` 或自定义拾取脚本）→ 加进 `LootTable.entries` |
| 新货币（钻石） | 新加一个 `PlayerDiamond` 组件 + 新事件，**不要塞进 `PlayerWallet`**（变化原因不同） |
| 掉落概率调整 | 只改 `LootTable` 资产，不动代码 |

## 3. 商店系统 ★（你说理不清思绪的那个）

### ① 组成：一共 7 个东西，分三层

```
【数据层】 ScriptableObject
  ShopItemData  ← 一个"商品"：名字/图标/价格/类型/效果参数
  ShopData      ← 一家"商店"：店名 + 商品列表

【逻辑层】 场景里的组件
  ShopNPC       ← 商店的"身体"：Trigger 检测玩家 + 头顶提示 + 按 E 打开面板
  ShopPanel     ← 商店的"界面逻辑"：列商品、算钱、发奖
  PlayerWallet  ← 玩家有多少钱
  PlayerInventory / PlayerCombat ← 买到的东西放哪

【表现层】
  ShopPanel 里用 UIFactory 运行时生成的行（名字 + 价格 + Buy 按钮）
```

**打开方式只有一条路**：`ShopNPC` 调 `ShopPanel.Instance.Open(shopData)`。
**`ShopPanel` 是单例**（`Instance`），因为场景里只有一个商店界面，多个 NPC 共用一个面板。

### ② 数据流（从按 E 到东西进背包）

```
玩家走进 ShopNPC 的 Trigger
  └ ShopNPC.OnTriggerEnter2D → playerNear = true
       └ Update 里每帧上报 → InteractionPrompt.Show() 头顶出现 "Press E"
            └ 按 E → ShopPanel.Instance.Open(shopData)
                 └ ShopPanel 从 PlayerWallet/PlayerCombat/PlayerInventory 拿引用
                      └ Refresh()：遍历 shopData.items，每件生成一行
                           └ 点 Buy → TryBuy(item)
                                ├ wallet.TrySpend(item.price)  ← 钱不够直接 return（按钮也会置灰）
                                ├ itemType == Weapon      → playerCombat.AddWeapon(item.weapon)
                                └ itemType == Consumable  → playerInventory.AddItem(item, 1)
                                     └ 广播 InventoryChange → InventoryPanel 刷新
```

### ③ 配置清单（**照这个从头配一遍**）

**Step 1：建商品资产**

`Project 右键 → Create → Data → Shop Item`，每个商品一个：

| 字段 | 说明 | 例（治疗药剂） | 例（钥匙） |
|---|---|---|---|
| `itemName` | **必须英文**（项目字体只有 ASCII） | `HEALTH POTION` | `KEY` |
| `icon` | 图标（可空） | 药水图 | 钥匙图 |
| `price` | 售价 | `30` | `30` |
| `itemType` | **决定买完去哪** | `Consumable` | `Consumable` |
| `weapon` | `itemType = Weapon` 时才用 | 空 | 空 |
| `consumableType` | 消耗品效果类型 | `Heal` | `None` |
| `healAmount` | `Heal` 的回血量 | `40` | 不生效 |

> **`itemType` 是最关键的字段**，它决定 `ShopPanel.TryBuy` 走哪个分支：
> `Weapon` → 进武器栏（Q 切换）；`Consumable` → 进背包（B 打开，点 Use 生效）

**Step 2：建商店资产**

`Create → Data → Shop Data`，一个场景一家店就够：

| 字段 | 说明 |
|---|---|
| `shopName` | 面板标题（英文），例 `SHOP` |
| `items` | 把 Step 1 的商品拖进来 |

**Step 3：场景里放 NPC**

选中 `Sign` → **Ctrl+D 复制** → 在副本上：
- **Remove Component** `SignPost`
- **Add Component** `Shop NPC`
- `Shop Data` 拖 `ShopData.asset`
- `Prompt Text` = `Press E`（头顶提示文字）

> 为什么让你复制 Sign：它已经有正确的父物体（Environment）、触发碰撞体、图层和排序。
> 从零建一个要自己调这些，容易漏。

**Step 4：确认面板在场景里**

```
Canvas
├── ShopPanel       ← 空物体 + ShopPanel 脚本（已加好）
└── InventoryPanel  ← 空物体 + InventoryPanel 脚本（已加好）
```

这两个物体**在 Awake 里会隐藏自己的内容**，所以看到它们"是空的"是正常的 —— UI 是运行时由 `UIFactory` 生成的。

**Step 5：确认玩家身上有这三个组件**

```
Player
├── PlayerWallet      ← 金币
├── PlayerCombat      ← 武器栏（买武器进这里）
└── PlayerInventory   ← 道具栏（买消耗品进这里）
```

### ④ 扩展点

| 想加什么 | 改哪里 | 要不要改代码 |
|---|---|---|
| 多卖一个商品 | 新建 `ShopItemData` → 拖进 `ShopData.items` | **不用** |
| 调价格 | 改资产上的 `price` | **不用** |
| 加一种新的消耗品效果 | 在 `ConsumableType` 枚举加一项 + `PlayerInventory.ApplyEffect` 加一个 case | 要 |
| 加"买完解锁区域"这类效果 | ⚠️ 分支会变多 → 这时候才该抽 `IPurchaseEffect` 接口 | 要（重构） |
| 场景里多开一家店 | 再建一个 `ShopData` + 复制一个 ShopNPC | **不用** |

### ⑤ 常见问题排查

| 现象 | 原因 |
|---|---|
| 按 E 没反应、头顶没提示 | Trigger 碰撞体没勾 `Is Trigger` / 父物体没选对 / Tag 不是 `Player` |
| 面板打开了但是空的 | `ShopData.items` 是空的，或者拖的是空资产 |
| 点 Buy 没反应 | 钱不够（按钮会置灰）—— 先捡金币 |
| 买了东西背包里没有 | 按 **B** 打开的是 `InventoryPanel`；买的如果是**武器**，它在武器栏（按 Q 切），不在背包 |
| 买完面板不刷新 | `TryBuy` 末尾有 `Refresh()` ✓ 如果没有就是代码被改了 |

## 4. 背包系统（InventoryPanel）

### 组成

```
InventoryPanel（永远激活，只负责听 B 键）
└── Content（真正显示/隐藏的子容器）
     ├── Title "INVENTORY"
     ├── -- WEAPONS (Q / click) --
     │    └── 每把武器一行：名字 + Equip 按钮
     └── -- CONSUMABLES --
          └── 每个道具一行：名字 x数量 + Use 按钮
```

### 数据流

```
按 B → Toggle() → 切 Content 显隐 → Refresh() 重建列表
   ├ 武器列表 ← playerCombat.weaponInventory（数据源在 PlayerCombat）
   └ 道具列表 ← playerInventory.slots（数据源在 PlayerInventory）
点 Equip → playerCombat.SelectWeapon(index)
点 Use   → playerInventory.UseItem(item)
              └ ApplyEffect：Heal 类型 → PlayerHealth.Heal(healAmount)
                 （满血时返回 false，**不消耗道具**）
```

### 配置：**没有字段要配**

数据全部来自玩家身上的两个组件。

### ⚠️ 关键设计点（这个坑你刚踩过）

**为什么要有 `Content` 子容器？**

```csharp
// ❌ 错误写法
private void Awake() { gameObject.SetActive(false); }   // 自己关自己

private void Update() { if (Input.GetKeyDown(KeyCode.B)) Toggle(); }  // 永远不执行
```

**Unity 的规则：GameObject 未激活时，不调它的 `Update`。** 所以"用某个键开关自己"的 UI **绝不能把自己 SetActive(false)** —— 必须留一个常驻节点听按键。

正确结构：**自己常驻 → 隐藏内容子容器**。

### 扩展点

| 想加什么 | 改哪里 |
|---|---|
| 显示道具图标 | `Refresh()` 里给每行加一个 `Image` |
| 分类页签 | `Refresh()` 拆成多个 Tab |
| 新的消耗品效果 | `ConsumableType` 加枚举 + `PlayerInventory.ApplyEffect` 加 case |

## 5. 武器系统

### 组成（**每把武器 = 一个数据资产 + 一个外观预制体**）

```
IronSword.asset (SwordWeapon)
├ weaponName / damage / cooldown / attackRange / knockbackForce
├ useMeleeSwing = true          ← 决定"只在挥砍时显示 + 绕握把旋转"
├ heldVisualPrefab → Sword 预制体
└ attackOriginChildName = ""    ← 近战留空（用玩家身上的 AttackPos）

Sword 预制体（原点在【握把】上）
├ Sprite            ← 贴图（自己调好角度/偏移）
└ WeaponHitbox 组件 + BoxCollider2D(IsTrigger)
```

### 为什么"每把武器一个预制体"

剑的枢轴在手柄、枪的枢轴在握把 + 枪口位置不同 —— **共用一套必然对不齐**。
做成预制体后，握把位置/朝向/挂点全由武器自己决定。

### 数据流（按 K 攻击）

```
按 K → Lua attack 状态 → PlayerCombat.Attack()
   ├ 近战：Feedback.SoundAt(AttackSwing)  ← 空挥也有声音
   ├ currentWeapon.Attack(holder)
   │    ├ 有 WeaponHitbox → 跳过圆形判定（伤害交给碰撞盒，防止一刀打两次）
   │    └ 没碰撞盒 → OverlapCircleNonAlloc 扫全部 + GetComponentInParent
   ├ 显示 VisualRoot → 打开碰撞盒 BeginSwing → 播放挥砍曲线
   └ 挥完 → EndSwing（关碰撞盒）→ 延迟 weaponShowAfterSwing 秒隐藏
```

### 配置清单

**`WeaponData`（资产上）**

| 字段 | 说明 |
|---|---|
| `weaponName` | 背包里显示的名字（英文） |
| `damage` / `cooldown` / `attackRange` / `knockbackForce` | 数值 |
| `useMeleeSwing` | **勾上 = 近战**（只在挥砍时显示）；**不勾 = 远程**（一直拿在手上） |
| `heldVisualPrefab` | 外观预制体 |
| `attackOriginChildName` | 外观预制体里当攻击点的子物体名（枪写 `Muzzle`，剑留空） |

**`LaserWeapon` 额外字段**（channel 型）

| 字段 | 说明 |
|---|---|
| `laserRange` | 激光长度 |
| `fireInterval` | 按住时每隔多久打一次（小 = 高频） |
| `recoveryTime` | 松开后的后摇 |
| `useKnockback` | 激光一般关掉（高频不打断敌人） |
| `channelAnimName` / `recoveryAnimName` | 发射/后摇的 Animator 状态名 |

**`WeaponHitbox`（挂在武器的外观预制体上）**

| 字段 | 值 | 说明 |
|---|---|---|
| `targetLayer` | `Enemy` | 打谁 |
| `hitbox` | 留空 | 留空 = 用自己身上的 `Collider2D` |
| `hitStop` / `shake` / `hitSfx` | 0.05 / 0.25 / Hit | 命中反馈 |

**⚠️ 三个必须记住的点**

1. `WeaponHitbox` **必须和碰撞体在同一个 GameObject 上** —— Unity 2D 物理的回调**只发给碰撞体所在的物体**（不做父子冒泡）
2. 碰撞体必须勾 **`Is Trigger`** —— 不勾的话剑会**物理推动敌人**而不是"划过"
3. 预制体的**原点要放在握把上** —— 挥砍是绕根节点旋转的，原点在图中心会变成"风车"

**Player 预制体上**

| 字段 | 值 |
|---|---|
| `PlayerController.Weapon Holder Transform` | `WeaponHolder` |
| `PlayerCombat.weaponInventory` | 初始武器列表 |
| `PlayerCombat.swingDuration` / `maxSwingAngle` / `weaponShowAfterSwing` | 挥砍手感（0.25 / 120 / 3） |

### 扩展点

加一把新武器 = **做一个外观预制体 + 新建一个武器资产 + 拖进 `weaponInventory`（或放进商店）**。代码零改动。

## 6. 交互系统（头顶提示 + 按 E）

### 组成

```
InteractionPrompt（全局唯一，运行时自动创建，不用你在场景里摆）
   └ 自带一个 Overlay Canvas（sortingOrder 100，不会被 HUD 挡）

可交互物（4 种，写法一致）
 TreasureChest / SignPost / ShopNPC / Door
   ├ 各有一个 Trigger 检测玩家
   ├ Update 里每帧「上报」：InteractionPrompt.Show(this, promptText, 锚点)
   └ 离开时 Hide
```

### 数据流

```
玩家进入 Trigger → playerNear = true
   └ 每帧 InteractionPrompt.Show(this, "Press E", 头顶坐标)
        └ Prompt 在 LateUpdate 里：世界坐标 → 屏幕坐标 → 摆到物体头顶
   └ 按 E → 各自的动作（开箱 / 弹面板 / 开商店 / 开门）
玩家离开 → Hide（**不调也会自动隐藏**，见下）
```

### 三个设计要点（都很关键）

1. **"每帧上报否则自动失效"**
   没上报就隐藏。这样物体被销毁/禁用、或者你忘了调 `Hide`，都不会在屏幕上留一个卡住的提示 —— **"幽灵 UI"是这类系统最常见的 bug**。

2. **同一帧先上报的赢**
   两个可交互物挨在一起时，不做仲裁就会每帧互相抢，文字疯狂闪烁。

3. **锚点用 `Renderer.bounds.max.y` 自动算**
   贴图顶边中点。箱子/牌子/门多大都自动对，不用一个个配高度。

### 配置清单

每个可交互物上：

| 字段 | 说明 |
|---|---|
| `promptText` | 头顶文字（**英文**，留空 = 不显示） |
| 其他 | 各系统自己的（`TreasureChest.lootTable`、`Door.requiredKey`…） |

**必须有一个 Trigger 碰撞体**（`Is Trigger` 勾上）用来检测玩家。

### ⚠️ 排错：头顶没提示 / 按 E 没反应

| 检查项 | 说明 |
|---|---|
| Trigger 勾了 `Is Trigger` 吗 | 不勾 = 玩家被挡住，永远进不了触发区 |
| **触发器和脚本在同一个物体上吗** | **2D 物理回调不做父子冒泡** —— 触发器做成子物体、脚本在父物体上 → 收不到 |
| Tag 是 `Player` 吗 | Unity 的 Tag **区分大小写**，`player` 匹配不上 |
| 物体在 `playerLayer` 能碰到的层吗 | Project Settings → Physics 2D 的层碰撞矩阵 |

### 扩展点

加一种新交互物 = 复制一个现成的（比如 Sign）→ 换组件 → 在 `Update` 里调 `InteractionPrompt.Show` + 按 E 时做自己的事。

## 7. 音效系统

### 组成

```
SoundLibrary（SO 资产，1 个）
├ sfx: 22 条 Entry
│    ├ id          ← SfxId 枚举
│    ├ clips[]     ← 放多个就随机播一个
│    ├ volume
│    └ pitchJitter ← 音高随机（打击音尤其需要）
└ bgm + bgmVolume

AudioManager（挂在 GameManager 上）
├ library → 拖 SoundLibrary
├ sfxVoices = 12   ← 声部池大小
└ masterVolume
   └ 内部：12 个 AudioSource 的池 + 1 个 BGM 源
```

### 调用方式（代码里只有一行）

```csharp
AudioManager.Play(SfxId.Jump);                    // 2D 音效
AudioManager.PlayAt(SfxId.Hit, transform.position); // 带位置（有距离衰减）
Feedback.Sound(SfxId.PlayerHurt);                 // 也可以走 Feedback
```

### 配置清单

| 步骤 | 做什么 |
|---|---|
| 1 | `AudioManager` 挂到 **GameManager** 物体上 |
| 2 | `Library` 字段拖 `Assets/Data/SoundLibrary.asset` |
| 3 | 打开该资产 → 22 条 id 已经铺好 → **往里拖 clip** |
| 4 | BGM 拖到最下面的 `Bgm` 字段，`Bgm Volume` 建议 0.35 |

**没配的 id 自动静音，不报错** —— 所以可以边跑边补素材。

**音效素材建议**：每个动作在 `Clips` 里放 **2~3 个**，配合 `pitchJitter` 0.1 左右，连击时听不出重复。

### 优先级（按"性价比"排）

```
必配：Hit 命中 · AttackSwing 挥砍 · Jump 跳跃 · Coin 金币 · PlayerHurt · EnemyDeath
建议：Land 落地 · Dash 冲刺 · ChestOpen 开箱 · UIClick 按钮 · PlayerDeath
氛围：BGM
```

### 扩展点

加音效 = 在 `SfxId` **枚举末尾追加**一项 → 资产里会自动多出一条 → 拖 clip → 代码里 `AudioManager.Play(SfxId.新项)`。

> ⚠️ 枚举项**只能加在末尾**。插在中间会让已经配好的资产 id 全部错位。

## 8. 打击感系统（Feedback + CameraShake + HitStop）

### 组成

| 类 | 作用 |
|---|---|
| `Feedback` | **统一入口**：一次调用 = 顿帧 + 震屏 + 音效 + 特效 |
| `HitStop` | 顿帧：把 `Time.timeScale` 压到 0 一小段真实时间 |
| `CameraShake` | 震屏（零依赖版本，挂 Main Camera 即可） |

### 为什么要有 `Feedback` 这一层

命中反馈散落在近战/激光/投射物/陷阱/被击七八个地方，**每个地方各写一遍必然会漏**（你的项目原来就是"近战有顿帧，但没震动、没音效"）。

收敛成一个静态入口后：**调手感只改一处**，新加的武器默认就有完整反馈。

### 调用方式

```csharp
Feedback.Hit(worldPos, hitStop: 0.05f, shake: 0.25f, sfx: SfxId.Hit, vfxPrefab);
Feedback.Sound(SfxId.UIClick);
Feedback.SoundAt(SfxId.Coin, transform.position);
Feedback.Shake(0.7f);
```

### 强度约定（照这个配，手感才统一）

| 场景 | hitStop | shake |
|---|---|---|
| 激光命中（高频） | **0.02** | 0.12 |
| 近战命中 | 0.05 | 0.25 |
| 玩家被打 | — | 0.35 |
| 玩家死亡 / Boss 落地 | — | 0.5~0.7 |

> **高频武器顿帧必须更短**，否则会变成"卡顿感"而不是打击感。

### ⚠️ 一个已经踩过的坑

原来用的是 `CinemachineImpulseSource` —— 但**场景里根本没有 Cinemachine**（没有 Brain / ImpulseListener），所以 `GenerateImpulse()` 调了**完全没有效果，也不报错**。

`CameraShake` 是零依赖版本：只操作 `Transform`，Perlin 噪声 + 平方衰减。

### 配置

| 步骤 | 做什么 |
|---|---|
| 1 | `CameraShake` 挂到 **Main Camera** |
| 2 | 调 `Max Offset`（0.35）/ `Damping`（1.8）/ `Frequency`（22） |

## 9. 敌人系统

### 组成

```
Enemy（基类，挂在所有敌人身上）
├ 数值：maxHealth / damage / attackRange / chaseSpeed / territoryRange / visionHeight
├ 行为参数：stopDistance / minDistance / windupTime / attackCooldown / lungeSpeed
├ 新增：showHealthBar / enableRegen / regenDelay / regenPerSecond
├ 状态机：EnemyStateMachine（11 个 EnemyState 子类）
├ 血条：EnemyHealthBar（Awake 自动补上，不用你配）
└ 生命周期虚方法：GetPostHurtState / GetCombatReturnState / CanStartAttack
                    MoveHorizontal / StopHorizontal
                    OnTelegraphTick / OnTelegraphEnd / UpdateVisuals

SlimeEnemy（继承 Enemy，只覆写"怎么动"和"怎么表现"）
FlyingEnemy（继承 Enemy，覆写回归状态 + 视野阈值 + 自己的技能）
```

### 9.1 血条（`EnemyHealthBar`）

**不用配置** —— `Enemy.Awake` 会自动补上这个组件。想关就在 `Enemy.showHealthBar` 取消勾选。

| 字段 | 默认 | 说明 |
|---|---|---|
| `size` | (1.1, 0.14) | 条的大小 |
| `heightOffset` | 0.15 | 离贴图顶部多高 |
| `hideWhenFull` | **false** | 满血也显示（勾上 = 只在受伤时冒出来） |
| `showDuration` | **0** | 0 = 一直显示；>0 = 受伤后显示这么久 |

**三个实现坑（都处理了）**：
1. 敌人靠 `localScale.x = -1` 翻转 → 子物体血条会被镜像 → **每帧把血条的 X 缩放取成和父物体同号**抵消
2. 血条会被场景光照压暗 → **材质强制用不受光的 `Sprites/Default`**
3. 贴图不用准备 → 运行时用 **1×1 白图**生成，所有血条共用

### 9.2 脱战回血

| 字段 | 默认 | 说明 |
|---|---|---|
| `enableRegen` | 勾 | 总开关 |
| `regenDelay` | 3 | 多久没被打算脱战 |
| `regenPerSecond` | 6 | 每秒回多少 |

**判定** = 一段时间没被打 **且** 看不见玩家。

**一个必须处理的细节**：血量是 `int`，每帧 `currentHealth += 6 * deltaTime` 会被截断成 0 → **永远不回血**。所以用 `regenAccumulator` 先攒小数，攒够 1 点才真的加。

### 9.3 追击三段式（`ChaseState`）

```
玩家 < minDistance   → 主动后退，保持出手距离
玩家 ≤ stopDistance  → 刹停，等冷却 → 蓄力 → 冲撞
否则                 → 靠近
```

| 字段 | 史莱姆建议 | 说明 |
|---|---|---|
| `stopDistance` | **3** | 停在哪等攻击（给冲撞留助跑距离） |
| `minDistance` | **1.2** | 玩家贴太近就退开（**0 = 不后退**，会黏在玩家身上） |

⚠️ **顺序不能反**：必须先判"太近"。反过来的话贴着玩家时会一直命中"已到位"分支，永远不后退 —— 这正是 Boss 之前贴脸的同一个 bug 结构。

⚠️ **字段名不能叫 `keepDistance`** —— `FlyingEnemy` 已经有同名字段，**基类和子类同名字段 Unity 不支持**。

### 9.4 蓄力可读性（`TelegraphState` + 钩子）

```
ChaseState 决定攻击
  └ CanStartAttack() 为 true 才切 TelegraphState
       └ TelegraphState 每帧调 OnTelegraphTick(progress 0→1)
            └ SlimeEnemy 覆写：按 progress 压扁（Y→0.55, X→1.35）
       └ 感叹号跟着进度脉动（12Hz → 30Hz）
       └ 蓄力期间 PhysicsUpdate 调 StopHorizontal（不许继续跳）
```

**`windupTime` 建议 0.5~0.6**（默认 0.3 玩家反应不过来）。

### 9.5 飞行 Boss 的高度分层

| 字段 | 建议 | 说明 |
|---|---|---|
| `keepDistance` | **7** | 水平距离小于这个就主动后退（**这个字段在 `FlyingEnemy` 上**，别和基类的 `minDistance` 搞混） |
| `chaseHeight` | 3.5~5 | 追踪目标是「玩家上方这么高」，而不是玩家本人 |
| `hoverHeight` | 3 | 待机时离出生点多高 |
| `diveRecovery` | 1.6 | **下坠打空后的低空硬直** = 玩家的偷伤害窗口 |
| `diveRecoveryOnHit` | 0.8 | 打中后的硬直（短，不惩罚成功的一方） |
| `diveStunDuration` | 1.2 | 冲撞命中给玩家的**眩晕**时长（0 = 关掉） |
| `diveDamage` | 25~35 | 命中的代价要够痛才值得躲 |
| `returnHomeDistance` | 3 | 丢了玩家之后飞回出生点 |

### 9.6 调试：按住 F1 看所有范围

```
按住 F1  或  菜单 Tools → 战斗范围显示（可常显）
```

**为什么用编辑器叠加层而不是 `OnDrawGizmos`**：
1. `OnDrawGizmos` 里用 `Input.GetKey` 在**编辑模式拿不到按键**（Game 视图没焦点就没输入）
2. Gizmos 在 **Game 视图要额外打开 Gizmos 按钮**才显示
3. `OnDrawGizmosSelected` / `CustomEditor.OnSceneGUI` 都要求**先选中物体**，怪物一多没法对比

`RangeDebugOverlay`（在 `Assets/Editor/`）用 `SceneView` 的 KeyDown/KeyUp 事件 + 遍历所有敌人，一次全画出来。

## 10. UI 体系：场景搭 vs 运行时生成

你的项目**两种都有**，这不是混乱，是**按"要不要经常调外观"分的**：

| 类型 | 用在哪 | 为什么 |
|---|---|---|
| **场景里手搭** | 血条、金币文字、GameOver 面板、主菜单按钮、牌子面板 | 需要**反复调位置/贴图**的东西，必须能在 Editor 里所见即所得 |
| **运行时生成**（`UIFactory`） | 商店商品行、背包列表、胜利面板兜底 | **内容数量不固定**，只能在运行时按数据生成 |

### `UIFactory` 的 API

```csharp
UIFactory.CreatePanel(parent, name, color, sprite, type)  // 面板（可带九宫格贴图）
UIFactory.CreateText(parent, name, content, size)          // 文字
UIFactory.CreateButton(parent, name, label, onClick, bg)   // 按钮（自动带点击音）
UIFactory.Center(rt, anchoredPos, size)                    // 锚到父物体正中心
```

### ⚠️ 一个必须记住的坑

**代码 `new` 出来的 `RectTransform` 锚点是不确定的**（编辑器菜单创建 UI 时 Unity 会帮你设锚点，代码创建不会）。不显式设锚点，`anchoredPosition` 的含义就不确定，UI 会整体偏到角落。

所以 `UIFactory.CreateText/CreateButton` 内部**都会调一次 `Center()`**，让 `(0,0)` 统一等于"父物体正中心"。

### 字体警告

| 字体 | 字符数 | 汉字 |
|---|---|---|
| `DungeonFont SDF`（HUD 用的） | 94（纯 ASCII） | **0** |
| `LiberationSans SDF`（TMP 默认） | 拉丁字母 | **0** |

**所有运行时 UI 的文字必须用英文**，否则显示成方框。注释、Tooltip、Debug.Log 可以随便用中文（不走 TMP 字体）。
